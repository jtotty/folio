Option A — Inline service object

Do the work synchronously inside the controller's transaction.

Shape

flowchart LR C[Controller] --> S[Service] S --> D[(DB)]

Sketch

class OrdersController < ApplicationController
  def accept
    Order.transaction do
      @order.accept!
      ManufacturingOrderCreator.call(@order)
    end
    redirect_to @order
  end
end

Tradeoffs

  • Simple control flow — one transaction, one place to read.
  • Slow requests when the work grows.
  • Failures roll back the whole accept action.
  • No retry semantics for transient errors.

Cost

build: ~0.5d · risk: low · LOC: ~80
Pick this if The downstream work is fast (<100ms) and atomicity with the parent action matters more than throughput.
